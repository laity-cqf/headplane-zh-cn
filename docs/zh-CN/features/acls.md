# 访问控制

[English](/features/acls)

本指南适用于基于 `tale/headplane` 0.8.2 的社区维护仓库 `laity-cqf/headplane-zh-cn` 的 **0.8 发布线**。保留上游 MIT 许可证原文及原作者版权声明，**不是 Headplane、Headscale 或 Tailscale 官方中文版**。

Headscale 将访问控制列表（ACL）存储为单个 HuJSON 策略。“访问控制”页面提供两种编辑方式：使用可视化表单修改常用部分，或直接编辑原始策略文件。

## 使用条件

通过 Web 界面写入策略，需要在 Headscale 配置中使用数据库策略模式：

```yaml
# Headscale 的 config.yaml
policy:
  mode: database
```

使用 `file` 模式时，页面为只读并显示原因。编辑还需要 `write_policy` 权限；`owner`（所有者）、`admin`（管理员）和 `network_admin`（网络管理员）拥有此权限。读取策略仍需原有的 `read_policy` 权限。切换界面语言不改变权限或策略模式。

## 规则

“规则”选项卡包含五类列表：

- **访问规则**对应 `acls` 部分，允许一组来源访问一组目标。目标必须包含端口或端口范围，例如 `tag:web:80,443`。未填写端口时，编辑器自动补上 `:*`，表示所有端口；Headscale 不接受缺少端口的目标。可选的协议字段将规则限制为单一协议，如 `tcp`、`udp` 或 `icmp`。
- **Grants（授权规则）**对应 `grants` 部分。目标不带端口，端口和协议单独填写，如 `tcp:443`；可选 `via` 标签限制流量经过的子网或出口网关。需要 Headscale 0.29 或更高版本；旧版本隐藏此列表，并拒绝保存包含 Grants 的策略。`app` 应用能力保留，在文件中编辑。
- **自动批准者**对应 `autoApprovers` 部分，按用户、用户组或标签自动批准节点宣告的子网路由或出口路由。审批不等于流量授权，仍需配置访问规则或 Grants。
- **SSH 规则**对应 `ssh` 部分，控制节点间的 Tailscale SSH 访问、本地 Unix 用户身份，以及 `accept` 或 `check` 模式。`check` 模式可填写重新认证周期，例如 `12h`。
- **主机别名**对应 `hosts` 部分，为 IP 地址或 CIDR 网段设置名称，以便规则引用。

添加或编辑条目会打开弹窗。来源、目标和 SSH 用户使用可添加或移除的标签块；页面将已知的用户组、标签、主机别名及 Headscale 用户提供为快捷建议。访问规则必须填写来源和目标，SSH 规则还必须填写 SSH 用户。

主机别名只能包含小写英文字母、数字和连字符，并沿用上游首字符必须为字母或数字的规则；名称不可重复，地址不能为空。此处不增加上游没有的地址校验，策略是否有效仍由 Headscale 判断。

## 子网路由与自动主备切换

进入“子网路由”，按网段查看网关的在线、宣告及审批状态。“当前主用”直接来自 Headscale 返回的主用路由。“管理网关”进入设备详情，沿用现有权限批准或撤销路由。点击“刷新路由”重新获取快照；此页面不测量流量或内网健康。

在两台或更多能够访问同一内网的网关上宣告并批准完全相同的网段。例如，在 `router-a`、`router-b` 上均宣告 `10.0.0.0/16`，分别批准该网段，并保持客户端接收子网路由。Headscale 负责选择主用并管理故障切换，面板不提供固定优先级或负载均衡控制。切换后，已有连接可能需要重连。

候选数量只统计同时宣告且已批准该网段的网关，包括离线候选。网关在线不代表内网连接一定正常。验收主备时，停用一台网关，检查同一内网服务能否经另一台继续访问，随后恢复网关。

普通自动主备无需填写 `via`。已有 Grants 如果通过 `via` 限制网关，需确保两台都带有允许的标签，否则可能排除备用网关。“当前主用”是 Headscale 的全局选择，不代表每个客户端实际采用的路径。

这些新增功能属于维护分支源码。已锁定的 `v0.8.2-zh` 发行和 `v0.8.2` 镜像保留原发布内容，正式镜像随下一个上游版本交付修正。

## 标签与用户组

“标签与用户组”选项卡管理 `groups` 和 `tagOwners`。

- **用户组**将 Headscale 用户组织为团队。策略中使用 `username@` 引用用户。用户组名称必须以 `group:` 开头，之后仅含小写英文字母、数字和连字符，首字符不能为连字符。
- **标签**按用途标识设备，而非按所有者标识。每个标签列出允许分配该标签的用户和用户组，并显示当前使用此标签的设备。名称必须以 `tag:` 开头，后续字符规则与用户组相同。

名称重复或不符合规则时无法确认。新建弹窗预填的 `group:`、`tag:` 只是前缀，需要继续填写名称。

标签必须先在 `tagOwners` 中声明。Headscale 允许将未声明的标签分配给设备，但策略规则不会匹配它；“设备”页面的标签弹窗会对此发出警告，并提供返回访问控制页面的链接。

也可以在“用户”页面通过行菜单中的“编辑用户组”修改成员关系，用户名称下会显示所属组。两处修改的是同一个策略的 `groups` 部分。成员关系保存在策略中，而非独立的 Headscale 用户字段中。

## 编辑文件与预览更改

“编辑文件”使用原有的 CodeMirror 编辑器编辑 HuJSON。“预览更改”将草稿与已保存版本作差异比较。可视化编辑、文件编辑和差异预览共用同一份草稿；只有点击“保存”才会将它发送到 Headscale。点击“放弃更改”恢复已保存版本。

::: warning 可视化编辑会移除注释
HuJSON 允许注释和尾随逗号。Headplane 可以读取这些内容，但可视化编辑会重新生成策略文本并移除注释。检测到注释时，“规则”和“标签与用户组”会显示警告。需要保留注释时，使用文件编辑器。
:::

未提供表单的顶层字段（如 `nodeAttrs`、`tests`）及规则中的未知字段会随策略保留。未知动作值按原文显示并保留，不能被自动改写成允许操作。显式空的 `acls: []`、`grants: []` 会保留，避免删除最后一条规则后改变访问控制语义。

“预览规则”沿用上游尚未实现的占位提示，不执行网络访问模拟。策略是否被接受取决于实际运行的 Headscale 版本；汉化不会让旧版本支持新的语法。此发布线原有集成测试矩阵仍为 0.27.0、0.27.1、0.28.0、0.29.0 和 0.29.1。

## 语言切换与错误诊断

使用页面顶部的语言按钮选择英文或简体中文。页面、弹窗、权限提示、本地校验、解析说明、编辑器查找及差异预览控件随语言切换，未保存的策略和弹窗草稿会保留，切换本身不会提交策略。

策略字段名、`accept`、`check`、`group:`、`tag:`、用户名、别名、IP、端口和时长等真实值不翻译。已知动作可以显示中文标签，但写回的仍是原始标识。

策略无法解析时，可视化页面显示原因，仍可进入文件编辑器修正。原始 JavaScript 或 Headscale 诊断会保留在中文说明旁，便于排查。保存被拒绝时，已保存策略不会被替换。文件模式下策略文件缺失时，会显示创建文件或切换数据库模式的解决说明；其他接口故障保留原始诊断信息。

完整文档汉化与镜像、部署验收仍在进行，参阅[语言与维护说明](/zh-CN/features/language)。
