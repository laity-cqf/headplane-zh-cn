# Headscale 0.29 网页管理

此非官方社区分支为 Headscale 0.29 增加管理表单。既有配置继续可用，打开页面不会自动启用能力或修改网络。以下功能属于镜像 `v0.8.3` 发布后的维护分支变更，需要安装之后包含这些功能的新发行版。

## 策略能力与测试

打开**访问控制 → Headscale 0.29 功能**。保存需要数据库策略模式及策略修改权限。文件模式保持只读，但仍可通过校验 API 检查草稿。

| 设置                  | 网页操作                                    | 作用                                                         |
| --------------------- | ------------------------------------------- | ------------------------------------------------------------ |
| `nodeAttrs`           | 添加目标和能力名称                          | 配置 NextDNS、MagicDNS AAAA、随机客户端端口及 Taildrive 能力 |
| `randomizeClientPort` | 切换整个网络的默认值                        | 请求随机客户端端口；仅此设置不能保证直连                     |
| `tests`               | 添加来源、协议、允许／拒绝的目标端口        | 验证 ACL 与 Grants 共同产生的策略行为                        |
| `sshTests`            | 添加来源、目标及 accept/deny/check 系统账号 | 验证 SSH 策略，不实际发起 SSH 连接                           |
| Grants `app`          | 编辑能力 JSON 或插入预设                    | 配置 Taildrive 或 Peer Relay 应用授权                        |
| SSH `check`           | 选择动作和重新验证周期                      | 要求重新验证；来源节点必须属于用户，不能是标签节点           |
| SSH `acceptEnv`       | 添加环境变量名或模式                        | Headscale 0.29.7+ 允许转发指定的 SSH 环境变量                |

保存前使用**预览规则 → 在 Headscale 上校验草稿**。Headscale 使用实时用户和节点解析策略并运行 `tests`／`sshTests`。校验不会保存草稿、替换当前策略，也不会测试实际网络连通性。确认结果后单独点击保存。断言失败时显示 Headscale 原始诊断并阻止保存。

表单保留无关规则与未知字段。可视化编辑会重新生成 HuJSON 并移除注释；需要保留手写注释时使用**编辑文件**。无法识别的配置段会原样保留，需要在文件编辑器中修正。

### Taildrive 与 Peer Relay

使用 `nodeAttrs` 给共享文件的节点授予 `drive:share`，给访问节点授予 `drive:access`。添加从访问者身份到文件服务器身份的 Grant，填写如下 `app` 参数：

```json
{
  "tailscale.com/cap/drive": [{ "shares": ["documents"], "access": "ro" }]
}
```

Taildrive 预设默认为只读；按需调整共享名称和访问模式。实际共享目录仍需在文件服务器的 Tailscale 客户端中配置，策略表单不能代替远端文件系统操作。

使用 Peer Relay 时，在相应 Grant 中添加 `tailscale.com/cap/relay` 应用能力，并在支持此功能的 Tailscale 客户端上启用中继服务器。网络需要时放行选定的中继 UDP 端口。Peer Relay、DERP 和子网路由主备选择是不同机制。

Headscale 尚不支持 Funnel 和 `nodeAttrs.ipPool`，页面不提供这些预设。按 Headscale 0.29.7 发行说明，使用 `acceptEnv` 前必须将 SSH 目标客户端升级到 Tailscale 1.104.4 或更高版本。

## 服务器设置

以具有身份与访问配置权限的账号打开**设置 → Headscale 设置**。将 `headscale.config_path` 对应文件以可写方式挂载后可编辑；仅通过 API 连接时服务器设置保持只读。

- 设置默认节点密钥有效期，例如 `180d` 或 `0`。影响之后的注册，不会批量重写已有设备的到期时间。标签节点不受此限制；客户端指定有效期或 OIDC 令牌有效期可能优先生效。
- 将临时节点离线清理时长设为大于 `65s`。
- 将主备探测间隔设为 `0` 以关闭探测，或设为至少 `2s`。开启时超时至少为 `1s` 且小于间隔，默认值分别为 `10s` 和 `5s`。两台网关必须宣告且获批相同子网。探测检查控制通道响应，不验证子网内每个目标。
- 设置默认客户端自动更新偏好。客户端可以自行覆盖，不会强制立即升级。
- 开启或关闭 Taildrop；此设置与 Taildrive 共享目录无关。

保存会写入相应 YAML 键。已配置 Docker 集成时，通过重启 Headscale 应用修改；其他部署需手动完整重启。稳定分支的进程和 Kubernetes 集成只发送 SIGHUP，无法应用这些启动参数，因此此页面不会调用它们。保存前阅读页面中的重启说明。环境变量可能覆盖文件值，需在部署配置中另行调整。表单过期时先刷新，避免覆盖较新的设置。

## 认证请求审批

打开**设置 → 认证请求审批**，粘贴请求者提供的完整 `hskey-authreq-…` ID，核对请求后选择**批准请求**或**拒绝请求**。不存在或已过期的 ID 会显示服务器错误。需要身份与访问配置权限；只读角色和 0.29 之前的 Headscale 无法执行操作。

Headscale 没有列举待审批会话或通过 ID 查询请求者身份的 API，因此页面无法提供自动审批队列。SSH check 仍可通过 OIDC 重新验证。新设备在“设备”页面注册并选择所属用户；0.29 使用 JSON `/api/v1/auth/register` 接口，旧服务器继续使用各自原有注册 API。

服务器监听地址、TLS 证书、DERP／STUN 监听、公网防火墙、客户端端口映射及远端共享目录仍需通过部署或客户端配置完成。面板不管理宿主机操作系统。
