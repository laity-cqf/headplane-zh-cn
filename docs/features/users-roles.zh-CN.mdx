# 用户与角色 [#users--roles]

Headplane 独立保存账号，与 Headscale 用户分开。首次通过 [SSO](/features/sso) 或[代理认证](/features/proxy-auth)登录时创建账号。角色决定在 Headplane 中的操作权限；与 Headscale 用户的关联决定哪些设备和认证密钥属于该账号。

## 角色 [#roles]

| 角色           | 权限                                                          |
| -------------- | ------------------------------------------------------------- |
| **所有者**     | 全部操作，包括转移所有权。始终只有一个所有者。                |
| **管理员**     | 除转移所有权外的全部操作。                                    |
| **网络管理员** | 管理 ACL、DNS 和网络设置；查看设备与用户；创建认证密钥。      |
| **IT 管理员**  | 管理设备、用户、设置和登录限制；可查看但不能修改 ACL 与 DNS。 |
| **审计员**     | 查看全部内容，并为自己创建认证密钥。                          |
| **查看者**     | 查看设备与用户，并为自己创建认证密钥。                        |
| **成员**       | 无法访问管理面板，只能看到帮助接入个人设备的首页。            |

  alt="成员首页"

第一个登录的人成为所有者。之后的新账号默认为成员，由所有者、管理员或 IT 管理员在**用户**页面修改角色。使用 SSO 时，也可给新账号指定其他默认角色，或从身份提供商读取角色，参阅[从身份提供商分配角色](/features/sso#roles-from-the-identity-provider)。

使用 Headscale API 密钥登录时拥有全部权限，不关联角色，参阅 [API 密钥](/configuration/api-keys)。

## 关联 Headscale 用户 [#linking-to-headscale-users]

每个账号可关联一个 Headscale 用户，从而拥有该用户的设备和认证密钥。审计员、查看者需要先关联才能为自己创建认证密钥；[浏览器 SSH](/features/ssh) 也使用此关联确定连接身份。

  alt="Headplane 设置中的认证密钥"

找到 SSO subject 或邮箱相同、且尚未被关联的 Headscale 用户时，Headplane 自动建立关联。登录时会尝试匹配；未关联账号每次打开 Headplane 时也会重试。因此，如果 Headscale 同样通过 SSO 创建用户，首台设备加入后就可以完成账号关联。subject 的匹配条件见 [SSO 文档](/features/sso#how-accounts-match-headscale-users)。

没有匹配用户时，账号保持未关联状态，直到手动关联。

### 手动关联 [#linking-by-hand]

所有者、管理员和 IT 管理员可在**用户**页面关联任意账号：

1. 如果还没有对应的 Headscale 用户，通过**添加用户**创建。
2. 打开账号行菜单，选择**关联 Headscale 用户**。
3. 选择尚未与其他账号关联的 Headscale 用户。

同一菜单中的**更改关联用户**可调整已有关系。账号必须先关联，才能修改角色。

通过 SSO 登录且尚未匹配的所有者、管理员和 IT 管理员，会在登录后看到**关联账号**页面，可选择自己的 Headscale 用户。选择**暂时跳过**可保持未关联，之后再从用户页面处理。

其他角色不能自行选择用户，因为关联会授予该用户设备和密钥的访问权。完成关联前，首页会提示联系管理员。

## 管理 Headscale 用户 [#manage-headscale-users]

用户页面同时显示未关联的 Headscale 用户。Headscale 不可用时仍显示本地账号，提示远端数据缺失，
不会当成空列表；无法读取策略时停用用户组编辑。

点击**添加用户**，填写用户名及可选显示名／邮箱。用户名至少两位，以 Unicode 字母开头，
允许字母、十进制数字、点、连字符和下划线，最多一个且不能位于末尾的 `@`。
新用户出现在未关联列表。OIDC 管理的用户不能重命名；重命名不自动修改策略引用。

删除用户前先移除其设备；Headscale 0.28+ 不支持重新分配节点所有者。删除无法撤销，
会解除 Headplane 账号关联但不会删除登录账号，之后 OIDC 登录可能重新创建服务端用户。
当前账号自己的行不提供删除关联用户的操作。

只有当前所有者可转移所有权，原所有者变为管理员；API 密钥会话不能代替账号所有者转移。

## 用户组和成员接入 [#groups-and-member-onboarding]

**编辑用户组**需要用户与策略修改权限，以及可读的数据库策略。选择已有组或输入有效的 `group:...` 名称。
保存保留其他成员和字段，但重新序列化会移除注释，并显示警告。文件模式保持只读。

成员看到**连接设备**、平台下载、Linux 安装脚本和当前网络的 `tailscale up --login-server=...` 命令。
页面区分已关联、等待首台 SSO 设备和需要管理员协助；这些操作不授予控制台访问权。
切换语言保留表单草稿、权限、角色标识、命令和原始诊断。
