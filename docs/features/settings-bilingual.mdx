### Auth keys

Open **Settings → Auth keys**. These keys register machines without interactive
sign-in; they are different from Headscale API keys. Owners, admins, network
admins and IT admins manage keys. Auditors and viewers manage only keys for
their linked Headscale user. Members cannot open this page. Link an account
before creating self-service keys; see [Users](/features/users-roles).

Use **Create key**, choose a user, or enable **Tag-only key** and add at least
one tag with management privileges. The `tag:` prefix is filled in automatically.
**Expires after (days)** accepts 1–365,000 days and defaults to 90. **Reusable**
allows more than one machine to join; **Ephemeral** removes machines after
they go offline. Copy the key or the generated `tailscale up` command from the
success dialog immediately. The full key is not shown again after closing it.

The number input can display locale grouping but submits the raw integer.
The server rejects grouped, fractional and unit-suffixed form values such as
`365,000`, `365.000` and `90 days` rather than truncating the expiry.
Filter by user and status; the default is **Active**, with newest keys first.
Active and expired filters follow the upstream expiration-time rules; used
keys have a separate badge. Tag-only listing and per-user fallback follow
the capabilities of Headscale. A partial loading failure preserves available
results and directs operators to the server logs.

**Expire** immediately prevents new registrations with an eligible user-owned
key; machines already registered remain connected. The availability of expiry
for tag-only keys follows upstream behavior. Self-service ownership is checked
on the server against the actual user's keys, including when form IDs are changed.

### Sign-in restrictions

**Settings → Sign-in restrictions** appears with a writable Headscale YAML file
at `headscale.config_path` and a usable OIDC configuration. Owners, admins and
IT admins can write. Other roles with user-read permission can inspect; members
cannot. Opening the route without usable OIDC returns a configuration error.

Add or remove **Email domains**, **Groups** and **Users**. Domains use hostnames
such as `example.com`, without a URL or email address. Groups and users use
the identity provider's original values. An empty list removes that category's
restriction; the removal dialog explains this before the last entry is removed.
Duplicates, invalid input and stale entries return errors without writing.

Changes update `oidc.allowed_domains`, `oidc.allowed_groups` and
`oidc.allowed_users`, preserving comments and unrelated settings. Both Headscale
and Headplane enforce them. Restart Headscale to apply changes, or configure an
[integration](/configuration/integrations) for automatic restarts. Without one,
the page shows a restart notice. A “Saved, but Headscale didn't come back” error
means the YAML was written, without rollback. Inspect logs and restore service.

### Agent status

The Agent requires Headscale {versions.headscale.agent} or newer, a valid
`headscale.api_key` and the `integration.agent.enabled: true` configuration shown
in the examples below. Docker images and the NixOS module include the binary; native installs
must provide it. Follow [Headplane Agent](/features/agent) for configuration,
persistent state and ACL visibility. The status page displays configuration
results and triggers syncs; it does not edit the Agent configuration.

Roles with machine-read permission can inspect the page and use **Sync now**;
members cannot. Disabled, missing-key, unsupported-version and initialization
states explain why the Agent is unavailable. When enabled, the page shows
consecutive errors, sync and process times, the refresh interval, the Agent
machine, address and Tailscale version. A pending registration includes the
approval link.

**Coverage** excludes the Agent itself. Machines missing from the last sync
retain older details and timestamps, usually because they are offline or hidden
by ACLs. When the machine list cannot be fetched, it shows **Unavailable** while
keeping sync status visible. Chinese explanations retain original diagnostics,
including unknown errors. Language selection does not change permissions,
configuration, intervals or machine data.

### Configuration examples

```yaml
integration:
  agent:
    enabled: true
```
