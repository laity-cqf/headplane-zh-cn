# 访问控制 [#access-control]

Headscale 将访问控制列表（ACL）保存为单份 HuJSON 策略。**访问控制**页面提供两种编辑方式：用于规则、标签和用户组的结构化编辑器，以及用于完整策略的文件编辑器。

## 前提条件 [#requirements]

只有 Headscale 使用数据库策略模式时，才能通过 Web 界面写入策略：

```yaml
# Headscale config.yaml
policy:
  mode: database
```

使用 `file` 模式时，页面只读并显示原因。只有所有者、管理员和网络管理员可以编辑策略。

## 规则 [#rules]

**规则**标签页将策略分成五类：

- **访问规则**：对应 `acls`，允许一组来源访问一组目标。目标包含端口范围，例如 `tag:web:80,443`。输入目标时省略端口会自动补充 `:*`，因为 Headscale 不接受没有端口的目标。
- **授权规则**：对应 `grants`。与访问规则相似，但端口和协议使用独立字段（例如 `tcp:443`），目标不包含端口。**经由**可让流量通过带指定标签的子网路由器或出口节点；通过出口节点访问互联网时，目标使用 `autogroup:internet`。可在授权弹窗中编辑应用能力（`app`）JSON，使用 Taildrive 只读或 Peer Relay 预设；新授权默认没有 IP 权限，需明确选择协议和端口。授权规则需要 Headscale {versions.headscale.grants} 或更新版本，旧版本隐藏此列表。
- **SSH 规则**：对应 `ssh`，包括 `check` 模式及其检查周期。
- **主机别名**：对应 `hosts`，为 IP 地址或 CIDR 网段命名，供规则引用。
- **自动批准者**：对应 `autoApprovers`。指定用户、用户组或标签所宣告的子网路由和出口节点无需手动批准。

添加或编辑条目时，通过弹窗中的标签项构建来源和目标。tailnet 中已有的用户组、标签、主机别名和 Headscale 用户会作为建议提供。

## 子网路由与自动主备切换 [#subnet-routes-and-automatic-failover]

进入**子网路由**，按网段查看网关的在线、宣告及审批状态。**当前主用**直接来自 Headscale 返回的主用路由。**管理网关**进入设备详情，沿用现有权限批准或撤销路由。点击**刷新路由**重新获取快照；此页面不测量流量或内网健康。

在两台或更多能够访问同一内网的网关上宣告并批准完全相同的网段。例如，在 `router-a`、`router-b` 上均宣告 `10.0.0.0/16`，分别批准该网段，并保持客户端接收子网路由。Headscale 负责选择主用并管理故障切换，面板不提供固定优先级或负载均衡控制。切换后，已有连接可能需要重连。

候选数量只统计同时宣告且已批准该网段的网关，包括离线候选。网关在线不代表内网连接一定正常。验收主备时，停用一台网关，检查同一内网服务能否经另一台继续访问，随后恢复网关。

普通自动主备无需填写 `via`。已有授权规则如果通过 `via` 限制网关，需确保两台都带有允许的标签，否则可能排除备用网关。**当前主用**是 Headscale 的全局选择，不代表每个客户端实际采用的路径。自动批准者只影响审批，不授予流量访问权限。

社区维护版 `v0.8.3-zh` 和镜像 `v0.8.3` 包含这些新增功能，上游基础仍为 0.8.2。JSON/HuJSON 策略可使用 `acls`、`grants` 或两者混合写法，多来源、多目标及协议/端口列表会完整展示并保留。`v0.8.2` 镜像保留原发布内容，发布状态以 GitHub Releases 为准。

## 标签和用户组 [#tags-and-groups]

**标签和用户组**标签页管理 `groups` 和 `tagOwners`。

- **用户组**：将多个 Headscale 用户组织在一起，供规则引用。成员写为 `username@`，这是 Headscale 策略引用用户的格式。
- **标签**：按用途而非所有者标识设备。每个标签列出允许分配该标签的用户和用户组，并显示当前带该标签的设备。

标签必须在 `tagOwners` 中声明才会生效。Headscale 允许给设备分配未声明标签，但任何规则都不会匹配它。**设备**页面的标签弹窗会对这类标签显示警告，并链接到访问控制页面。

也可在**用户**页面行菜单的**编辑用户组**中修改成员关系。用户所属组会显示在名称下方。两个入口都写入同一策略的 `groups`。

## 直接编辑文件 [#editing-the-file-directly]

**编辑文件**标签页编辑原始策略，**预览更改**显示与已保存版本的差异。结构化编辑器修改同一编辑缓冲区，因此可视化更改在保存前就会出现在文件和差异视图中。

文件编辑器实时检查 HuJSON 并标记语法错误，存在语法错误时无法保存。**格式化**应用两空格缩进和一致间距，保留现有换行、注释和尾随逗号。

只有点击**保存**后，才会将策略发送到 Headscale。

:::warning[结构化编辑不保留注释]
HuJSON 支持注释和尾随逗号。Headplane 能读取它们，但结构化编辑器会重新生成策略文本，导致注释丢失。加载的策略含注释时，规则、标签和用户组标签页会显示提示。需要保留注释时，使用文件编辑器。
:::

顶层扩展配置与未知字段会原样保留。节点属性和策略测试可在新增的“Headscale 0.29 功能”中编辑。

在“预览规则”中使用服务器校验可检查草稿而不保存。全部入口见 [Headscale 0.29 网页管理](/features/headscale-029)。

## 草稿、语言与校验 [#drafts-language-and-validation]

弹窗、文件编辑器和预览共用本地草稿，切换语言保留内容。**放弃更改**恢复加载的策略。
未知规则动作不会被改成 `accept`，加载失败也不会变成空白可编辑策略；保存仍需服务端权限和数据库模式。

用户组和标签名称分别使用 `group:`、`tag:`，后接小写字母、数字或连字符；重复名称会被拒绝。
重命名或删除条目后检查规则引用，用户引用继续使用 `username@`。

查找、替换、格式化、位置和诊断支持中英切换。Headscale 校验失败保留原始诊断和 HTTP 状态，并附所选语言说明。
**预览规则**调用真实服务端校验草稿而不保存，不模拟内网可达性；详见 [Headscale 0.29 网页管理](/features/headscale-029)。
