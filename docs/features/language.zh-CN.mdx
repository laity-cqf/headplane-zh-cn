# 语言与维护说明 [#language-and-maintenance]

此功能属于基于上游 [tale/headplane](https://github.com/tale/headplane) 的社区维护仓库 `laity-cqf/headplane-zh-cn` 的 `main` 分支，**不是 Headplane、Headscale 或 Tailscale 官方中文版**。保留上游 MIT 许可证原文及原作者版权声明。

双语稳定版 `v0.8.2-zh` 已发布，正式镜像为 `ghcr.io/laity-cqf/headplane-zh-cn:v0.8.2`（amd64/arm64），双语文档保留源码及发行快照，不部署托管站点。`stable` 已完成语言基础、登录、公共界面、设备、用户、角色、账号关联和成员下载页，以及访问控制的五类可视化编辑器、文件编辑、差异预览及诊断，并配有对应双语指南；现已补齐 DNS、设置（预授权密钥、认证限制和 Agent）、浏览器 SSH，以及完整 VitePress 双语文档、导航、搜索和历史更新日志。语言切换保留表单草稿与 SSH 会话；翻译及容器验收已通过，正式发布结果以 GitHub Releases 为准。该发布线保留原有首页关联入口、权限、用户名规则和兼容要求。部署维护版本前，需要核实构建和发布状态。

## 界面语言 [#interface-language]

在登录页或管理界面顶部选择 **简体中文** 或 **English**。偏好保存在浏览器的 `headplane_locale` Cookie 中，有效期一年，登录前后均有效，不改变账号、权限、Headscale 配置或其他浏览器。

首次访问按 `Accept-Language` 选择英文或简体中文。中文语言变体统一使用简体中文，其他不支持的语言回退到英文。清除 `headplane_locale` 后恢复跟随浏览器语言。

登录、公共导航、设备、用户、访问控制、DNS、设置和浏览器 SSH 均已支持两种语言，包括表单、校验、操作结果、连接提示、公共错误、日期和相对时间。用法见[设备](/features/machines-bilingual)、[用户](/features/users-roles)、[访问控制](/features/acls)、[DNS](/features/dns-bilingual)、[设置](/features/settings-bilingual)和[浏览器 SSH](/features/ssh)操作指南。

配置键、API 字段、命令、产品名称、用户输入值、远端终端输出和原始诊断保留原文。中文错误会附带解释及原始诊断详情。切换语言不会改变时区，也不会重建 SSH 会话。

## 文档语言 [#documentation-language]

在文档页顶部选择 **中文** 或 **EN**。英文保留原有 URL，中文使用 `/zh-CN/` 前缀。历史版本保留版本前缀，例如 `/0.8/zh-CN/install/docker`。切换语言保留当前页面、查询参数和锚点。文档语言由 URL 决定，与应用 Cookie 独立。

导航、正文、搜索结果、更新日志和升级说明随语言切换。搜索使用真实双语索引，并按当前语言筛选。原文使用锚点的页面，其中文标题保留对应英文引用锚点。沿用上游的截图明确标注为英文截图，不冒充中文界面截图。

维护文档站部署前，应用内文档按钮继续指向上游英文站。安装示例使用上游镜像或 flake 时会说明来源，不代表这些上游产物包含本仓库翻译。

## 维护界面翻译 [#maintaining-interface-translations]

英文资源位于 `app/i18n/en.ts`，简体中文位于 `app/i18n/zh-CN.ts`。模块资源（例如 `en/machines.ts` 和 `zh-CN/machines.ts`）由这两个入口汇总。TypeScript 检查消息键，单元测试和翻译检查校验插值占位符是否一致。

React 使用 `useI18n()`，服务端操作使用 `getLocale(request)` 和 `translate()`。包含行内代码或带样式名称的句子使用 `Message`，确保整句能按语言重排。时间格式化函数显式传入语言。不使用进程级变量保存用户语言，避免请求间互相影响。

## 维护文档 [#maintaining-documentation]

英文文件与对应 `.zh-CN.md` 或 `.zh-CN.mdx` 放在同一目录。各目录的 `meta.json` 和 `meta.zh-CN.json` 管理导航。站内链接写作 `/install/docker`：渲染器添加语言，React Router 添加历史版本前缀。命令、标识符和配置值保持不变，版本值统一来自 `docs/app/lib/versions.ts`。

中文标题使用 `[#english-anchor]` 保留外部引用及切换语言后的锚点。同步更新 `CHANGELOG.md` 和 `CHANGELOG.zh-CN.md`，保留版本标题、日期、引用及发布解析器使用的 `Upgrading`、`Changes`、`Fixes` 结构标记，由渲染器翻译这些标签。

## 检查翻译更新 [#checking-translation-updates]

提交前运行 `pnpm i18n:check`。**Translations** 工作流会在 PR 和维护分支推送时运行同一检查，覆盖缺失或空白消息、占位符、文档配对、导航顺序、发布结构标记及常见硬编码界面文案，包括无障碍标签、对象标签、Toast 和 `ActionError` 消息。

`.github/i18n/reviewed.json` 分别记录中英文消息对、文档对及共享文档源码的复核指纹。只修改英文也会要求复核。共享文档代码变化是复核提醒，并不代表中文一定有错。检查命令不会更新记录。

先审阅差异、翻译发生变化的含义，并保留命令及配置值，再仅记录已核对的项目：

```bash
pnpm i18n:review --message common.dismiss
pnpm i18n:review --file docs/install/docker.mdx
pnpm i18n:review --file docs/app/components/header.tsx
pnpm i18n:check
```

文档对使用英文源文件路径；参数可重复。复核一项不会放行其他改动。源文件删除时，同时删除对应中文文件，再对旧英文路径或消息键执行复核以移除记录。格式化应在复核前完成。初始化参数 `--initialize` 拒绝覆盖已有基线。

技术名称和示例在 `.github/i18n/exceptions.json` 中记录，必须有确切消息键，或确切文件与代码文本，并说明理由。失效例外会导致检查失败。新增例外需逐项审阅，不用宽泛排除或未经核对的全量刷新绕过失败。

静态检查不能证明翻译质量，也无法追踪全部动态字符串、第三方组件或远端终端消息。仍需人工检查源码差异和两种语言的操作流程；原始服务端诊断继续保留，并附中文解释。检查范围见 `session/MAINTENANCE.zh-CN.md 第 8 节`。

上游更新会创建同步 PR 和跟踪 Issue，列出翻译工作及上述复核命令。提醒不会自动完成翻译，本身也不阻止合并；需要强制门禁时，在 GitHub 分支保护中配置必需状态检查。容器 CI 已通过，stable 的翻译及容器验收已通过，正式发布结果以 GitHub Releases 为准。双语文档通过源码阅读、`pnpm docs:dev` 本地预览，或从 GitHub Releases 下载对应版本快照；不部署托管文档站，也不需要托管凭据。仓库内 `session/MAINTENANCE.zh-CN.md` 说明了发布配置。

## 固定维护分支与历史发行

社区维护仓库只保留两条长期分支：`main` 跟随上游开发，`stable` 跟随上游最新正式发行标签。上游升级后继续更新 `stable`，不为每个版本新建分支；兼容范围和构建工具随对应上游版本保持一致。

社区版本标签例如 `v0.8.2-zh`。每个已发布版本都在 GitHub Releases 保留源码、双语文档快照、正式多架构镜像的摘要和校验和。Docker 完整镜像标签使用 `vX.Y.Z`，例如 `v0.8.2`；GitHub Release/Git 标签保留 `-zh`。完整镜像标签不重复使用；`latest`、`0.8` 可以前移。后续仅发布普通正式镜像，保留 amd64/arm64。源码使用 GitHub 自带 ZIP/tar.gz，后续发行不再附加重复的源码包。默认沿用上游版本，不添加修订号。明确要求提前交付维护修正时，可在 `.github/fork-release.json` 单独记录社区补丁版本，绑定真实上游提交并附双语发行说明。社区 0.8.3 基于上游 0.8.2，增加 JSON/HuJSON 的 ACL、Grants 兼容。下次升级上游时清除或重新绑定此覆盖记录；若标签已占用，选择下一个未使用的社区版本。旧镜像、标签和附件保持原样。临时 PR 分支合并后自动删除。

本项目是非官方社区维护版本，完整保留上游 MIT 许可证及来源说明。验收门禁和操作步骤见仓库内的 `session/MAINTENANCE.zh-CN.md`。

工作流保留 5 个：**Build**（编译、单元/集成测试、Nix 和容器运行验收）、**Translations**、**Docs**（根路径/归档预览）、**Upstream sync** 和 **Release**。Release 同时负责上传恢复及匿名镜像检查。现有不可变发行及历史调试镜像继续保留。
