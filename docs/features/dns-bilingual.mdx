# DNS guide

This guide describes `laity-cqf/headplane-zh-cn` on `main`. The development branch does not publish Docker images; deploy a published stable community release. See [Language and maintenance](/features/language) for release status.

### Access and applying changes

Select **English** and open **DNS**. Set `headscale.config_path` in Headplane to
the Headscale YAML file, using a path visible inside the Headplane container.
The page is unavailable without a readable configuration. Owners, admins and
network admins can write; IT admins and auditors can inspect; viewers and
members cannot open the page. Read-only configurations prevent writes in both
the interface and the server action.

General settings, nameservers and search domains update the YAML file while
preserving comments and unrelated keys. Restart Headscale to apply them, or
configure one [integration](/configuration/integrations) to restart it
automatically. Without an integration, the page shows the restart notice.
The “Saved, but Headscale didn't come back” error means the configuration was
written; it was not rolled back. Inspect Headscale's logs and restore service
before continuing.

### General, nameservers and search domains

**Rename** changes the tailnet base domain. Devices may behave unexpectedly
until they receive the new name. **Magic DNS** controls device-name resolution.
**Override local DNS** requires at least one global nameserver; disable it before
removing the last global server. Each toggle submits independently and shows a
save error when the change fails.

Use **Add nameserver** with an IPv4 or IPv6 address. Hostnames and DoH URLs are
not accepted. **Restrict to domain** creates split DNS for that domain and its
subdomains, retaining the upstream Tailscale 1.8 minimum for split DNS.
Reorder within the global list or a split-domain list; other lists are unchanged.
Keyboard focus follows the moved row and boundary arrows are disabled. Removing
the last server for a split domain removes that domain. Duplicate, stale and
out-of-bounds changes return errors without writing the configuration.

**Search domains** lists suffixes tried for short names. Add, reorder or remove
them with the corresponding controls. The Magic DNS domain stays first when
enabled and cannot be moved or removed from this list. Duplicate suffixes are
rejected.

### DNS records

**Add record** accepts A records with IPv4 and AAAA records with IPv6. A domain
can have one of each type; duplicate domain/type pairs are rejected. Removing
one type preserves other records. Domain names, addresses, record types and
configuration keys keep their original values in both languages.

Headplane edits records only through the JSON array in Headscale's
`dns.extra_records_path`. Create a writable file with the format shown in the configuration examples below.
Headscale watches the file and applies record changes without a restart or
integration. Use Headplane's `headscale.dns_records_path` if the container sees
the file at a different path; Headscale still needs `dns.extra_records_path`.
Inline `dns.extra_records` remain read-only, as do files without write permission.
Follow the [integration guide](/configuration/integrations) for shared paths and
automatic restarts.

### Configuration examples

```yaml
# Headplane config.yaml
headscale:
  config_path: "/etc/headscale/config.yaml"
```

```yaml
# Headscale config.yaml
dns:
  extra_records_path: /var/lib/headscale/extra-records.json
```

```json
[{ "name": "intranet.example.com", "type": "A", "value": "100.64.0.3" }]
```
